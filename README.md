# WaterCow 專案進度儀表板

繁體中文、唯讀、無後端的公開任務摘要。應用程式原始碼及內部文件不在此程式庫。

## 本機驗證

使用 Node.js 24，無需安裝套件：

```sh
node --test
node scripts/build.mjs
```

將 `dist/` 交給本機靜態 HTTP 伺服器即可預覽。請勿以 `file://` 開啟（瀏覽器模組及資料讀取需要 HTTP）。

## 更新資料

由獲授權維護者在本機先更新正式來源的 `origin/main`，再執行：

```sh
node scripts/refresh.mjs <正式來源的乾淨本機工作目錄>
node --test
node scripts/build.mjs
```

匯出器只讀取符合 `origin/main` 的乾淨來源，並僅輸出主要任務編號、已審查繁體中文標題、階段、狀態、負責人標籤與來源版本／時間。不得複製來源文件或整個私人程式庫。新任務必須先補充並審查 `catalog.json` 的翻譯；已存在任務若變更含義，維護者也必須重審翻譯。審查資料差異後以一般分支及合併請求更新。

這是**人工更新的資料快照**，不是即時治理平台。沒有跨程式庫存取權杖、瀏覽器登入、客戶資料、追蹤分析或資料寫入。畫面會提醒超過七天的來源版本。共同負責表示來源列有共同或人工負責人；歷史作者、共同審查及保留的共同決策權不會取代主要負責人，也不代表目前工作已被認領。

## 發布

1. 完成獨立審查及所需檢查，合併至 `main`。
2. 在 GitHub Pages 設定選擇 GitHub Actions 作為來源；保留應用程式程式庫的私人設定。
3. 手動執行 **Verify and publish dashboard**。只驗證時保留 `publish=false`；核准發布時在 `main` 使用 `publish=true`。
4. 工作流程須先通過 Linux 與 Windows 測試，再發布 `dist/` 的六個明確允許檔案。
5. 驗證網站、資料版本及手機版篩選功能。發現問題時以正常回復提交還原已驗證版本，再重新執行流程；不要改寫 Git 歷史。

所有 GitHub Actions 均固定至提交版本，部署使用短期 GitHub 權限，不需要新增私人來源的存取權杖。分支工作不自動部署；工作流程須由維護者手動啟動。公開程式庫可使用 GitHub 提供的標準執行器，不設定付費服務。
